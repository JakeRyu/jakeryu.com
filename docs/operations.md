# Operations

Part of the production setup lives in the Cloudflare dashboard and Google Search Console, not in this repository. This page records it so the site can be rebuilt or debugged later. It holds facts only: no secrets. Values were read from the dashboards on 2026-11-28.

## Worker and Git integration

The site is one Worker, `jakeryu-com`, using Workers Static Assets: no Worker script, only the build output.

`wrangler.jsonc` (in the repository):

- `name`: `jakeryu-com`.
- `assets.directory`: `./dist`, the Astro build output.
- `assets.not_found_handling`: `404-page`. Workers do not serve `404.html` on their own; without this, unknown URLs get Cloudflare's plain 404.
- `previews`: `{}`. Branch builds run `wrangler preview`, which requires this block even when it is empty.

Cloudflare dashboard, Workers & Pages > `jakeryu-com` > Settings > Builds:

| Setting | Production | Previews Base |
|---|---|---|
| Git repository | `JakeRyu/jakeryu.com` | same |
| Branch | `main` | Builds for Preview branches: on |
| Build command | `pnpm run build` | `pnpm run build` |
| Deploy / preview command | `npx wrangler deploy` | `npx wrangler preview` |
| Root directory | `/` | `/` |
| Build watch paths | include `*`, exclude none | include `*`, exclude none |
| API token | `jakeryu-com build token` | same |
| Build variables and secrets | none | none |
| Build cache | not recorded | on |

There is no `.node-version` file and no Node build variable, so the Node version is whatever the Cloudflare build image provides. pnpm is pinned by `packageManager` in `package.json`.

A push to `main` deploys to production; a push to any other branch builds a preview.

## Custom domain and DNS

The apex `jakeryu.com` is attached to the Worker as a custom domain. In the DNS records it shows as a locked, proxied record of type Worker pointing at `jakeryu-com`; Workers manages it, so do not edit it by hand. DNS setup is Full: Cloudflare hosts the zone.

| Name | Type | Content | Proxy |
|---|---|---|---|
| `www` | A | `192.0.2.1` | Proxied |
| `blog` | A | `192.0.2.1` | Proxied |
| `portfolio` | A | `192.0.2.1` | Proxied |
| `jakeryu.com` | Worker | `jakeryu-com` | Proxied |
| `jakeryu.com` | CAA | `0 issue "sectigo.com"` | DNS only |
| `jakeryu.com` | CAA | `0 issue "pki.goog"` | DNS only |
| `jakeryu.com` | CAA | `0 issue "letsencrypt.org"` | DNS only |
| `jakeryu.com` | TXT | `google-site-verification=…` (Search Console ownership; value omitted) | DNS only, TTL 1 hr |

`192.0.2.1` is a reserved documentation address (TEST-NET-1). The three `A` records are placeholders: nothing is served from that address. They exist and are proxied only so that requests to those hostnames reach Cloudflare, where the redirect rule runs.

There are no MX, SPF, DKIM or DMARC records, so the zone does not receive email.

## Redirects

One Redirect Rule (Rules > Redirect Rules > Single Redirects), named `Old subdomains to apex`. It sends the retired hosts to the apex.

- **Match:** custom filter expression

  ```
  http.host in {"www.jakeryu.com" "blog.jakeryu.com" "portfolio.jakeryu.com"}
  ```

- **Then:** URL redirect, type Dynamic, expression

  ```
  concat("https://jakeryu.com", http.request.uri.path)
  ```

- **Status code:** 301 (Permanent Redirect).
- **Preserve query string:** on.

Nothing else is mapped. A path with no equivalent on the new site returns 404 (spec: issue #1).

Check it:

```sh
curl -sI "https://blog.jakeryu.com/blog/x?q=1" | grep -iE "^HTTP|^location"
# HTTP/2 301
# location: https://jakeryu.com/blog/x?q=1
```

## HTTPS

SSL/TLS > Edge Certificates > Always Use HTTPS is on (switched on 2026-11-28). It handles every `http` request in the zone, so no redirect rule is needed for it. An earlier `Redirect from HTTP to HTTPS [Template]` rule was deleted the same day, because it duplicated this setting.

```sh
curl -sI "http://jakeryu.com/" | grep -iE "^HTTP|^location"
# HTTP/1.1 301 Moved Permanently
# location: https://jakeryu.com/
```

## Web Analytics

Cloudflare Web Analytics, a cookie-free beacon. Analytics & Logs > Web Analytics has one site, with configured hostname `jakeryu.com`, set to "Enable with JS Snippet installation" (not automatic injection, and EU visitors are not excluded). `src/layouts/Base.astro` includes the snippet on every page; the site token is `analyticsToken` in `src/site.ts`. The token is public by design.

## Search Console

A domain property for `jakeryu.com`, verified by the DNS TXT record above. The sitemap submitted is `https://jakeryu.com/sitemap-index.xml` (type: sitemap index, generated by `@astrojs/sitemap` at build time). On 2026-11-27 it was read successfully and reported 13 discovered pages.

## Rebuilding from scratch

1. Create the Worker from the Git repository with the settings in the first table.
2. Attach `jakeryu.com` as a custom domain.
3. Add the three placeholder `A` records, proxied, and the Redirect Rule.
4. Turn on Always Use HTTPS.
5. Create the Web Analytics site and check that the token in `src/site.ts` matches it.
6. Add the domain property in Search Console (a new TXT record is needed) and submit the sitemap.
7. Check the site and the redirects with `curl`.
